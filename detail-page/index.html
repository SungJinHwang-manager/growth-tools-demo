상세페이지 스크롤·클릭 분석

유료 히트맵 도구(뷰저블)의 트래킹이 멈춘 뒤, BigQuery에 적재된 GA4 이벤트로 상세페이지 스크롤 도달률과 클릭을 보기 위해 만든 도구다. 과정·기간·유입경로를 고르면 바로 계산되고, 두 조건을 나란히 비교할 수 있다.

스크롤 도달률

페이지를 연 사람 중 해당 깊이까지 내려간 사람의 비율이다. 옆 숫자는 직전 구간 대비 이탈(%p)이다.

가상 상세페이지 와이어프레임 · 진할수록 많이 도달

클릭 랭킹

클릭 제외 문구 (누르면 포함/제외가 바뀐다)

점 크기 = 클릭 수 (조건 A) · 회색 점 = 제외된 요소

산정 기준

스크롤

GA4 스크롤 이벤트의 깊이 값을 쓴다. 실제 사이트에서는 직접 심은 커스텀 깊이(20/50/70/90%)와 GA4 자동 수집(90% 고정)이 서로 배타적으로 기록되어, 한쪽만 보면 90% 도달자가 빠졌다. 그래서 두 값을 하나로 합쳐(COALESCE) 계산한다.

클릭

  • 클릭 이벤트의 텍스트 값을 공백 정리(TRIM) 후 같은 문구로 묶는다.
  • 같은 사용자 + 같은 시각(timestamp)의 클릭은 1회로 센다. 실측 과정에서 트래킹 스크립트가 한 번의 클릭을 여러 번 기록하는 문제를 발견했고, 원시 이벤트의 상당 부분이 이런 중복이었다. 데모의 '원시 이벤트 → 중복 제거' 숫자가 이 과정을 보여 준다.
  • GNB·푸터처럼 모든 페이지에 있는 요소는 상세페이지 내용과 무관해 랭킹에서 뺀다. 제외 목록은 담당자가 화면에서 직접 관리한다.

기준 일치 대신 기준 명시

유료 도구와는 집계 방식이 달라 숫자를 똑같이 맞출 수 없었다. 그래서 산정 기준을 화면에 적어 두고, 같은 기준 안에서 추세와 상대 비교(기수 간, 유입경로 간)를 보는 용도로 쓰기로 팀과 합의했다.

이 데모에 대해

실제 도구는 GA4 BigQuery 원천 데이터에 연결된 Streamlit 앱이다. 이 페이지는 같은 화면 구성을 정적 HTML로 옮긴 것이고, 데이터는 가상 데이터 마트(실제 마케팅 시트와 같은 구조의 가짜 데이터)의 일자별 조회수와 유입 캠페인을 바탕으로 생성했다. 과정명은 일반 명칭으로 바꿨다.
