01

상세페이지 분석기

유료 히트맵 도구 대체

문제

상세페이지 개편 이후 유료 히트맵 도구의 트래킹이 멈춰, 사람들이 페이지를 어디까지 보고 무엇을 누르는지 확인할 수 없었어요.

만든 것

GA4 BigQuery 원천 이벤트로 스크롤 도달률과 클릭 랭킹을 계산하는 대시보드예요. 과정·기간·유입경로를 고르고, 두 조건(예: 기수 간, 매체 간)을 나란히 비교할 수 있어요.

핵심 판단

  • 스크롤 깊이가 두 종류 이벤트에 나뉘어 기록되는 걸 발견하고 하나로 합쳐 계산했어요.
  • 한 번의 클릭이 여러 번 기록되는 트래킹 중복을 찾아, 같은 사용자·같은 시각 기준으로 제거했어요.
  • 유료 도구와 숫자를 똑같이 맞추는 대신, 산정 기준을 화면에 밝히고 같은 기준 안의 추세·비교용으로 쓰기로 했어요.

02

지원자·자소서 상시 분석

소재·메시지 발굴용

문제

매일 쌓이는 지원자 자기소개서에 "왜 지원했는지"가 담겨 있었지만, 양이 많고 테스트·무성의 응답이 섞여 있어 상시로 읽고 활용하기 어려웠어요.

만든 것

자소서를 지원 계기 9종·기대 7종·수준·품질 등급으로 분류하는 기준을 세우고, 매일 새로 쓰이거나 바뀐 자소서만 골라 분류하는 흐름을 만들었어요. 지원자 특성(성별·연령·전공·상태), 지원 완료까지 걸린 시간, 지원 시간대도 함께 봐요.

핵심 판단

  • 지원 상태가 바뀌거나 자소서를 나중에 쓰는 경우를 놓치지 않도록, 신규 행이 아니라 자소서 내용 변화를 기준으로 다시 분류해요.
  • 추가 비용 없이 운영해야 해서, 분류는 기존 구독 범위 안에서 돌리고 나머지 단계는 규칙 기반으로 자동화했어요.
  • 인사이트 문구는 태그 범위를 넘지 않게 쓰고, 하위 집단을 말할 땐 원문을 다시 세서 숫자를 붙여요.
