01

상세페이지 상시 분석 도구

스크롤·클릭 분석 · 유료 히트맵 도구 대체

문제

상세페이지 개편 후 유료 히트맵 도구의 트래킹이 멈추면서, 방문자가 페이지를 어디까지 보고 무엇을 누르는지 확인할 수 없게 됐다. 클릭·스크롤 데이터는 BigQuery에 쌓이고 있었지만 쿼리를 짜지 않으면 볼 수 없었다.

만든 것

BigQuery에 적재된 GA4 클릭·스크롤 이벤트로 스크롤 도달률과 클릭 순위를 계산하는 웹 도구다. 과정·기간·유입경로를 골라 조회하고, 기수 간·매체 간처럼 두 조건을 나란히 비교할 수 있다.

핵심 판단

  • 스크롤 깊이가 두 종류의 이벤트에 나뉘어 기록되고 있어, 둘을 합쳐 계산했다.
  • 한 번의 클릭이 여러 번 찍히는 트래킹 중복을 찾아, 같은 사용자·같은 시각의 클릭은 1회로 셌다.
  • 유료 도구와 숫자를 똑같이 맞추기는 어려워, 산정 기준을 화면에 적어 두고 같은 기준 안에서 추세와 비교를 보는 용도로 정했다.

마케팅 활용

콘텐츠별 스크롤·클릭 반응을 보고 상세페이지 개선 가설을 세우는 데 썼다.

02

지원서 데이터 상시 분석 도구

지원자 특성 · 자기소개서 분석

문제

지원자 특성이나 지원서 작성 행동을 보려면 어드민 데이터를 매번 내려받아 가공해야 했다. 자기소개서에는 지원 이유가 담겨 있었지만, 매일 쌓이는 데다 테스트·무성의 응답이 섞여 있어 꾸준히 읽고 활용하기 어려웠다.

만든 것

어드민 데이터로 연령·전공·재직 여부, 지원완료까지 걸린 시간, 지원 시간대를 보는 화면을 만들었다. 자기소개서는 지원 계기 9종·기대 7종·수준·작성 품질로 나누는 분류 기준을 세우고, 매일 새로 쓰이거나 내용이 바뀐 것만 다시 분류한다.

핵심 판단

  • 자기소개서를 나중에 채우거나 고치는 지원자가 있어, 새로 들어온 행이 아니라 내용 변화를 기준으로 다시 분류했다.
  • 추가 비용이 드는 구조는 쓸 수 없어, 분류는 기존 구독 범위 안에서 돌리고 나머지 단계는 규칙으로 자동화했다.
  • 인사이트 문구가 분류 범위를 넘지 않도록 했고, 특정 집단을 언급할 때는 원문을 다시 세어 숫자를 함께 적었다.

마케팅 활용

유입 타겟이 핵심 타겟과 맞는지 확인하고, 자기소개서에 드러난 고민을 소재·메시지 아이디어로 썼다.

데모 데이터 안내

  • 실제 마케팅 데이터 시트와 같은 구조(어드민 지원자 RAW, 매체 성과, GA4 전환, 페이지 조회수 등 23개 탭)로 가짜 데이터 마트를 만들었고, 두 데모는 이 데이터로 계산했다.
  • 지원자 이름·연락처·이메일과 자기소개서 문장은 모두 생성한 값이다. 과정명은 일반 명칭(예: 백엔드 27기)으로 바꿨다.
  • 규모·전환율·비용은 실제와 무관하게 정해, 숫자로 실제 성과를 짐작할 수 없다.
